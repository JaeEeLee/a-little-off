# 검색 노출(SEO) 작업 기록

> 2026-10-20 작업. 사이트가 구글 · 네이버 검색에 나오도록 한 일과, 앞으로 확인하거나 고칠 때 볼 내용을 정리했습니다.

| ----------------------------------------------------------------------- | ------------------------------- | ------------------ |
| 검색 엔진이 읽을 안내 파일 추가 (`robots.txt`, `sitemap.xml`)           | 이 저장소                       | 완료               |

## 먼저, SEO가 뭔가요

SEO(Search Engine Optimization, 검색 엔진 최적화)는 검색 엔진이 사이트를 **찾고**, **읽고**, **검색 결과에 보여 주기 좋게** 만드는 일입니다.
검색 엔진은 로봇(크롤러)이 사이트를 방문해 내용을 읽고, 자기 목록(색인)에 올린 뒤에야 검색 결과에 보여 줍니다.

1. **발견**: 로봇이 사이트 주소를 알아야 합니다 → 서치 콘솔 · 서치어드바이저에 등록하고 사이트맵을 냅니다.
2. **읽기 허락**: 어떤 주소는 읽고 어떤 주소는 읽지 말라고 알려 줍니다 → `robots.txt`, `noindex`
3. **이해**: 무엇에 관한 페이지인지 알려 줍니다 → 제목, 설명, 구조화 데이터
4. **색인**: 검색 엔진이 목록에 올립니다 → 우리가 할 수 있는 건 "색인 요청"까지이고, 나머지는 검색 엔진이 정합니다.

## 저장소에 한 일

### 1. `robots.txt` — 로봇에게 주는 출입 안내

사이트 주소 뒤에 `/robots.txt`를 붙이면 보입니다. 검색 엔진 로봇이 가장 먼저 읽는 파일입니다.

```
User-agent: *          # 모든 검색 로봇에게
Allow: /               # 사이트는 읽어도 되고
Disallow: /docent/     # 도슨트(전시장 전용)는 읽지 말고
Disallow: /tests/      # 테스트 · 문서 폴더도 읽지 말 것
Disallow: /docs/
Sitemap: https://a-little-off.pages.dev/sitemap.xml   # 페이지 목록은 여기에
```

### 2. `sitemap.xml` — 검색에 올리고 싶은 페이지 목록

검색에 나오게 하고 싶은 주소를 적어 두는 파일입니다. 지금은 메인(`/`) 하나뿐입니다.
페이지 내용을 크게 바꾸면 `<lastmod>` 날짜를 그날로 고쳐 두면 좋습니다.

### 3. `index.html` 머리의 검색용 정보

| 넣은 것                                                                    | 하는 일                                                                                                                              |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `<title>` "조금 이상한 우리들 · 이즈드로잉 단체전 \| 홍대 피시스 아카이브" | 검색 결과의 파란 제목. 사람들이 검색할 만한 낱말(단체전, 홍대, 피시스 아카이브)을 넣었습니다                                         |
| `<meta name="description">`                                                | 검색 결과 제목 아래 두세 줄 설명                                                                                                     |
| `<link rel="canonical">`                                                   | "이 페이지의 대표 주소는 `https://a-little-off.pages.dev/`"라고 알려 줍니다. `/#재이`처럼 꼬리가 붙은 주소가 따로 잡히지 않게 합니다 |
| `<meta name="robots" content="index, follow …">`                           | 메인은 검색에 올려도 된다는 표시                                                                                                     |
| `og:site_name`, `og:locale`                                                | 카카오톡 · SNS 링크 미리보기 보강 (기존 Open Graph에 추가)                                                                           |
| `<script type="application/ld+json">` 구조화 데이터                        | 아래 설명                                                                                                                            |
| `google-site-verification`, `naver-site-verification`                      | 사이트 주인이 맞다는 확인용 코드 (아래 "등록" 참고)                                                                                  |

**구조화 데이터(JSON-LD)** 는 사람에게는 안 보이고 검색 엔진만 읽는 "전시 정보 카드"입니다.
schema.org의 `ExhibitionEvent`(전시 행사) 형식으로 전시 이름, 기간(11/12 13:00 – 11/17 20:00), 장소(피시스 아카이브, 서울 마포구 신촌로 48), 입장료(5,000원), 주최(이즈드로잉)를 적었습니다.
구글이 이 정보를 쓰기로 하면 검색 결과에 날짜 · 장소가 함께 보일 수 있습니다(구글이 정하는 일이라 보장되지는 않습니다).

### 4. 작가 개인 페이지는 검색에서 빼기

`/jessie`, `/jessie/visit`은 지인에게 보내는 초대 · 예약 링크라서 모르는 사람이 검색으로 들어오지 않게 했습니다.

- `_headers`: 이 주소들에 `X-Robots-Tag: noindex, follow`를 붙입니다 (서버가 보내는 "검색 목록에 올리지 마세요" 표시).
- `assets/js/site.js`: 작가 페이지로 바뀔 때 페이지 안 `<meta name="robots">`도 `noindex`로 바꿉니다 (같은 뜻을 한 번 더).
- `/docent`는 원래부터 잠금 함수가 `noindex`를 붙입니다.

### 5. 테스트

`tests/e2e/seo.spec.js`가 위 내용이 빠지지 않았는지 확인합니다.
대표 주소, 검색 허용 표시, 구조화 데이터의 날짜 · 주소 · 입장료, 작가 페이지 `noindex`, `robots.txt` · `sitemap.xml` 내용을 봅니다.

## 바깥 서비스에 한 일

### 구글 서치 콘솔 (search.google.com/search-console)

1. **속성 추가 → URL 접두어** → `https://a-little-off.pages.dev/`
   - "도메인" 방식은 DNS 설정이 필요한데 `pages.dev` 주소는 우리가 DNS를 바꿀 수 없어서 "URL 접두어"를 썼습니다.
2. **소유 확인 → HTML 태그**: 받은 `<meta name="google-site-verification" …>`를 `index.html`에 넣고 배포한 뒤 "확인"
3. **Sitemaps** 메뉴에 `sitemap.xml` 제출
4. **URL 검사**에서 메인 주소 → "색인 생성 요청"

### 네이버 서치어드바이저 (searchadvisor.naver.com)

1. **웹마스터 도구 → 사이트 등록** → `https://a-little-off.pages.dev`
2. **소유확인 → HTML 태그**: 받은 `<meta name="naver-site-verification" …>`를 `index.html`에 넣고 배포한 뒤 "소유확인"
3. **요청 → 사이트맵 제출**: `https://a-little-off.pages.dev/sitemap.xml`
4. **요청 → 웹 페이지 수집**: `https://a-little-off.pages.dev/`

> 확인용 `<meta>` 코드는 비밀값이 아닙니다. 원래 누구나 볼 수 있는 페이지 머리에 넣으라고 주는 값입니다.
> **지우면 안 됩니다.** 지우면 다음 확인 때 소유권이 풀려 서치 콘솔 · 서치어드바이저를 쓸 수 없게 됩니다.

## 등록 직후 보이는 메시지와 뜻

| 메시지                                                                        | 뜻                                                                            | 할 일                                                                 |
| ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| "URL이 Google에 등록되어 있지 않음 · Google에는 아직 알려지지 않은 URL입니다" | 구글 로봇이 아직 한 번도 방문하지 않음. 새 사이트는 처음에 다 이렇게 나옵니다 | "실제 URL 테스트"로 읽을 수 있는지 보고, "색인 생성 요청" 후 기다리기 |
| "URL을 Google에 등록할 수 있음" (실제 URL 테스트 결과)                        | 로봇이 문제없이 읽을 수 있음                                                  | 기다리기                                                              |
| 사이트맵 상태 "가져올 수 없음"                                                | 등록 직후 흔함                                                                | 하루 이틀 뒤 다시 보기. 계속이면 주소 오타 확인                       |
| "URL이 Google에 등록되어 있음"                                                | 색인 완료. 검색에 나올 수 있는 상태                                           | 끝                                                                    |

보통 며칠에서 1~2주 걸립니다. 그 뒤 "조금 이상한 우리들 전시", "홍대 피시스 아카이브 전시" 등으로 검색해 봅니다.

## 앞으로 할 때

- **페이지 내용을 크게 바꿨을 때**: `sitemap.xml`의 `<lastmod>`를 그날로 → 배포 → 서치 콘솔 "URL 검사 → 색인 생성 요청", 서치어드바이저 "웹 페이지 수집" (선택)
- **검색에 나올 페이지를 추가할 때**: `sitemap.xml`에 `<url>` 추가 → 배포 → 사이트맵 다시 제출
- **작가 개인 페이지를 새로 만들 때**: `_headers`에 그 주소의 `X-Robots-Tag: noindex` 규칙도 함께 추가 (`site.js`의 `noindex` 처리는 자동)
- **전시가 끝난 뒤**: 구조화 데이터의 `eventStatus`는 그대로 둬도 됩니다(종료된 행사로 자연히 처리됨). 사이트를 내릴 계획이면 서치 콘솔 "삭제" 메뉴로 검색 결과에서 빨리 뺄 수 있습니다.
- **사이트 주소를 개인 도메인으로 옮길 때**: `canonical`, `og:url`, `og:image`, 구조화 데이터의 `url`, `robots.txt`, `sitemap.xml`의 주소를 모두 새 주소로 바꾸고, 서치 콘솔 · 서치어드바이저에 새 주소를 다시 등록합니다.
